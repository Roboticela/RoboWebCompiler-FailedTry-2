Why styles belong at build time

Mara Reyes · 8 min read · March 2026

A stylesheet that is resolved before your app ships cannot surprise it at runtime. This is the whole promise of a compiler-first UI toolkit.

When every declaration is lowered ahead of time, the runtime has nothing left to interpret. It receives a finished tree of boxes and paints them. No selector matching, no cascade, no recalculating style on every frame.

The fastest style is the one you never compute again.

That idea is old. What is new is the tooling: a compiler that can read ordinary HTML and CSS, validate them, and emit a native scene graph that a renderer can draw directly.

What changes for authors

Nothing you would notice. You still write classes, still think in flexbox, still debug with the same eye. The difference is when the work happens.
